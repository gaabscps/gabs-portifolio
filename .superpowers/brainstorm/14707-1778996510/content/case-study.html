— Methodology · how this got built
Honest breakdown of where AI helped, what I changed, what I rejected, and how I validated. The same template runs on every project — so you can compare across.
AI helped with
Boilerplate for Spigot plugin scaffolding, repetitive command handlers, event listener templates, and first drafts of economy/quest logic.
Tool: Claude (Sonnet 4.6, then Opus 4.7). Used as a faster keyboard, not as an oracle.
What I changed by hand
All economy balance numbers (AI's defaults were terrible). Edge cases in land claiming (AI missed concurrent claim conflicts). Player-facing copy — kept brincalhão, AI made it corporate.
Rule: if it touches taste or game-feel, I write it.
What I rejected
~30% of AI suggestions, mostly: over-engineered abstractions, unnecessary dependency additions, "enterprise" patterns for a Minecraft plugin, and one full plugin draft that would've broken in async events.
Receipt: 2 plugins rolled back after community testing exposed issues AI hadn't anticipated.
How I validated
Manual code review on every AI output. Test runs on staging server with 3 trusted players before public release. Public changelog + community vote on contested features. Postmortem when something breaks.
Principle: community feedback is the test suite.

Estrutura do case study (mesma em todos os projetos):

  1. Sticky breadcrumb (com traffic lights de assinatura) — sabe sempre onde está
  2. Hero: status pill + ano + categoria + título grande + 1-linha
  3. Cover visual — placeholder pra screenshot/preview real
  4. The why — pull quote em itálico com SUA frase real
  5. What it does — 3 feature cards (01/02/03)
  6. ★ Methodology — 4 blocos colorpostos: AI helped · changed by hand · rejected · validated
  7. Results — 4 stats grandes (qty plugins, tempo prod, rollbacks, % review)
  8. Stack — chips, com IA destacada
  9. CTAs: join/live + github + changelog
  10. Prev/Next — navegação entre cases

Por que essa estrutura resolve "responsabilidade":

A Methodology é repetível entre projetos. Você não precisa convencer ninguém de nada — só preencher honestamente os 4 blocos. Quem ler 3 case studies vê o padrão: "ele sempre declara onde IA entrou, onde mudou, onde rejeitou, como validou." Isso é responsabilidade demonstrada, não anunciada.
