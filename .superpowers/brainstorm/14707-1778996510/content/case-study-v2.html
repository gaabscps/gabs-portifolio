betterSMP · running since aug 2025
We built the Minecraft server we wished existed.
Most popular SMPs are abandoned AFK farms. You log in, find a corner, AFK overnight for diamonds. That's not playing. We wanted somewhere with actual things to do — and shipped 12 custom plugins to make it real.
▶
"Hyped Minecraft servers are AFK farms. Nothing to do, nothing new. We just wanted something better."
— me to my brother, late july 2025
build log
Real chronological notes. Where AI helped is marked in the margins — AI means I leaned on it for that part.
2025-08-14v0.1
Server up. First plugin scaffold.
Spigot setup, basic permission system, first economy plugin draft. Leaned hard on Claude AI for boilerplate — Spigot has a lot of ceremony and I wanted to skip the typing, not the understanding.
2025-09-02v0.4
Three plugins shipped. First rollback.
Economy, quests, custom mobs went live for 5 testers. Mobs broke async event handling on second day. AI-generated draft didn't anticipate concurrent spawns. Rolled back, rewrote by hand, learned the lesson the loud way.
⚠ rejected
The async pattern Claude suggested would have worked in a single-threaded test. Production never is.
2025-10-20v0.8
Community opens. Real testers, real bugs.
20 active players. They found edge cases that no AI prompt would catch — duped items via /enderchest in claimed land, exploit in custom enchanter, three race conditions in trading. Postmortems for each, written by hand.
▲ changed by hand
All economy balance numbers. AI's defaults were "let players have everything fast" — terrible game design. Taste decisions stay with me.
2026-02-10v1.4
12 plugins, weekly cadence, changelog public.
Every Friday I ship — new plugin, balance update, or fix. Community votes on contested features in Discord. AI writes the first 70% of code; I write all the copy, all the balance, and review every line.
★ rule
If it touches taste, game-feel, or player communication — I write it. Everything else is fair game for AI assistance.

what i'd change next time
I'd write the test plan before letting AI scaffold anything. The two rollbacks happened because I trusted AI's "this should work" without writing what "work" actually meant. Now I write acceptance criteria first, then prompt. AI is a faster keyboard — not a faster judgment.

O que mudou (vs v1):

LinguagemTrava em inglês. PT-BR vem via i18n (já existe no portfólio).
FormatoEra template AI (Methodology / Features / Stats). Virou longform build log com entradas datadas — lê como um post pessoal.
Honestidade AINão tem mais seção "Methodology". Vira marginalia: badges AI inline + notas na margem (★ rule, ▲ changed, ⚠ rejected) entrelaçadas no texto.
LayoutAssimétrico: sidebar sticky com TOC + meta + área de leitura larga. Não é o grid central de portfólio AI.
MotionReading progress no header. Underline desenha em hover dos links. Margin notes tiltam no hover. CTA com seta wiggling. Live preview com pulse-glow.
VozHeadings com personalidade ("We built the Minecraft server we wished existed", "what i'd change next time"), pull quote com timestamp humano ("— me to my brother, late july 2025").
Final sectionNão tem "Conclusion" template. Tem "what i'd change next time" — prosa honesta, mostra aprendizado real.

Aviso honesto: mesmo essa versão tem limitação — mockup HTML não consegue mostrar tudo que seria scroll-driven (sidebar destacando seção atual, count-up de stats quando aparece na viewport, etc.). Isso é trivial com Framer Motion na implementação real.
